> What is the `Backend`?
- Simple Analogy: Think of a restaurant:
1️⃣ The Frontend (Client/UI): This is the dining room where customers sit, look at the menu, and talk to the waiter. It's everything the user can actually see and touch (buttons, forms, pages).
2️⃣ The Backend (Server/Node.js): This is the kitchen. Customers never go inside the kitchen, but this is where all the actual work happens—chefs cooking the food, managing inventory, and following recipes.

- Simple Definition: The `backend` is the hidden part of an application that lives on a server. It handles business logic, processes user data, talks to databases, and decides what data to send back to the client.

> Note: `Instance`
- Simple Analogy: Think of a popular restaurant that gets too busy for just one front door. Instead of opening a new location across town, they open three identical copies of the restaurant right next to each other, sharing the exact same street address and front door. Each copy is an `instance`.
- Simple Definition: An `instance` is an independent, running copy of your Node.js application running in computer memory.

> What Does the `Backend` Actually Do?
1. Listens for Requests: It waits for the frontend or client to ask for something (like clicking a "Login" or "Get Notes" button).
2. Processes Logic: It runs code (like Node.js and Express) to figure out what to do with that request—checking if a password is correct or creating a new note.
3. Talks to the Database: It securely saves, updates, or deletes data using tools like Mongoose and MongoDB.
4. Sends Responses: It packages up the result (like a JSON object with your notes) and sends it back to the client so the user interface can display it.

> What is a `Server`?
A `server` is a computer (hardware) or a program (software) that listens for requests from clients (like your browser) and sends back a response (like data or a webpage).

Think of it like a waiter: the client places an order, and the server brings back the result.

Key Points to Remember:
1. Request-Response Cycle: Servers only act when a client sends a request.
2. Hardware vs. Software: Hardware is the physical machine; software (like Node.js or Nginx) handles the incoming web traffic.
3. Backend Role: Backend developers write the code that runs on these servers to handle business logic and databases.

> Core Definitions: Node.js, NPM, and Packages
- `Node.js`: A JavaScript runtime environment that lets you run JavaScript outside the web browser (like on your computer or a server) so you can build backend applications.

- `NPM (Node Package Manager)`: The default package manager for Node.js. It comes pre-installed with Node.js and does two things: acts as an online library for code packages, and acts as a command-line tool to install/manage them.

- `Package`: A reusable block of code written by other developers (like a toolkit or library) that you can download and use in your project to save time.

Key Points to Remember:
- `Node.js = Engine`: It translates JavaScript into machine code so your server can understand and execute it.

- `NPM`: App Store for Code: Instead of writing code from scratch (like encryption or connecting to a database), NPM lets you download pre-built code packages instantly using the terminal (e.g., npm install express).

- `Project`: In software development, a project is a self-contained directory containing your source code, configuration files, and dependencies organized to build a specific application or service.
Key Points to Remember:
1. Core Structure:It typically includes an entry point file (e.g., `index.js`), a metdata file (`package.json`), and a dependencies folder (`node_modules`).
2. Self-Contained: It houses everything required to run, test, and deploy the application independently.

- `package.json`: A special (metadata) file created in your Node.js project that acts as the "ID card" thus, keeping track of *project's dependencies* (all the packages your project depends on). However, those packages can have their own dependencies (sub-dependencies), forming a complete dependency tree managed automatically by *npm*.
In short, `package.json file` exists to act as the official blueprint or "ID card" for your Node.js project. It keeps track of essential project details and every package your application relies on to function correctly.
`package.json` is *human-edited*: You or npm add direct dependencies here.
e.g.: 
1. Your Project depends on cat-me (listed in your package.json).
2. cat-me depends on yargs (a package to handle command-line arguments).
3. yargs depends on camelcase (a helper package).
4. camelcase is independent (it has no further dependencies and sits at the bottom of the tree).

- `package-lock.json`: While *package.json file* only lists your direct dependencies, the *package-lock.json file* (automatically generated by npm) keeps track of the exact versions of every single package and sub-dependency (like yargs and camelcase) insatlled in your project to ensure your app doesn't break.
`package-lock.json` is *machine-generated*: NPM automatically updates and maintains this file behind the scenes—never edit it manually.

- Direct vs. Indirect Dependencies:
1. Direct: Packages that you install for your project (listed in package.json).
2. Indirect (Sub-dependencies): Packages that your packages need to run behind the scenes.

Key Points to Remember:
- Execution Policy: Windows restricts script execution by default to protect your PC from malicious scripts. `RemoteSigned` is a safe setting that allows local scripts (like npm) to run.
- Scope (`CurrentUser`): Using `-Scope CurrentUser `ensures the fix only applies to your Windows user profile without risking system-wide security changes.

> `Environment Variables` vs. `The .env file` vs. `dotenv package`
- Simple Analogy: Think of a restaurant's safe and manager's office:
*Hardcoded Values* (The Danger): Like taping your restaurant's master safe combination and bank passwords to the front window. Anyone walking past (or anyone looking at your code on GitHub) can see your sensitive data.
`Environment Variables` & `The .env file` (The Secure Safe): Like the manager's private lockbox hidden in the back office. It holds all your sensitive keys and passwords away from your public code files so they stay secure.

- Simple Definition: `Environment variables` are hidden configuration settings (like database URLs and secret keys) that change depending on where your app is running, and `the .env file` is the private text file where you store these secrets locally on your computer during development.

Simple Analogy: Think of the `dotenv package` like a secure messenger service that walks into your private back office (`.env`), reads your secret passwords, and securely delivers them to your application's running memory (`process.env`) so your code can use them without exposing them publicly.
Simple Definition: A *zero-dependency npm package* that loads environment variables from a `.env file` into `process.env` in Node.js, allowing you to manage confidential data and configuration settings safely.

> What are `index.js`, `app.js`, and `constants`?
Simple Analogy: Think of setting up a franchise restaurant headquarters:
- `index.js` (The Power Switch / Front Door): This is the master building entrance and the main light switch. Its only job is to turn the lights on, connect the utilities (database), and officially open for business.
- `app.js` (The Main Kitchen / Blueprint): This is where all the actual cooking happens. It organizes the kitchen stations, sets up the rules (middleware), and builds the menu (routes).
- `constants` (The Rulebook & Label Maker): This is the master binder of fixed, unchanging rules and labels (like standard pricing, fixed error messages, or role names) so you never have to guess or type them manually twice.

Simple Definitions:
- `index.js (or server.js)`: The entry point of your project. It imports your configured app and your database connection, then boots up the server (app.listen()).
- `app.js`: The core configuration file. It creates the Express application, sets up middleware (express.json()), and registers all your API routes (/notes).
- `constants`: A dedicated file (often named constants.js) used to store static, unchanging values (like database names, status codes, or user roles) in one place so your code stays clean and easy to update.

> What are `db`, `models`, `controllers`, `routes`, `middlewares`, and `utils`?
Simple Analogy: Think of a professional restaurant kitchen operation:
`db` (The Storage Room / Pantry): Like the walk-in refrigerator where all raw ingredients (data) are permanently stored and kept safe over time.
- `models` (The Recipe Cards / Blueprints): Like the strict kitchen rulebooks that dictate what exact structure and ingredients a dish must have before it is allowed into the storage room.
- `controllers` (The Chefs): Like the kitchen staff who take the order, perform the actual business logic, process the data, and prepare the final result to be sent back.
- routes (The Waiters): Like the front-of-house staff who listen for customer requests at specific tables (URL paths and HTTP methods) and direct them to the correct chef.
- `middlewares` (The Security Guards / Quality Checkers): Like the checkpoint staff who intercept requests at the entrance to inspect data, parse JSON, or verify permissions before letting anyone through to the kitchen.
- `utils` (The Helper Tools): Like standard multi-purpose kitchen gadgets (timers, blenders, or formatters) used for small, repetitive tasks across different stations.

Simple Definitions:
- `db (Database Connection)`: The file or logic responsible for establishing and maintaining a secure connection to your persistent database (like MongoDB).
- `models (Mongoose Schemas)`: The structure definition that tells Mongoose what fields, data types, and rules your documents must follow.
- `controllers (Business Logic)`: The functions that handle what happens when a route is hit—fetching data from the database, processing it, and sending the response.
- `routes (Endpoint Mapping)`: The mapping file that connects specific URL paths and HTTP methods (GET, POST, PATCH, DELETE) to their corresponding controller functions.
- `middlewares (Interceptors)`: Specialized functions that sit between the incoming request and the controller to process data, check authentication, or handle errors. (Note: *Intercept* means to stop something while it is on its way from one place to another, before it reaches its final destination.)
- `utils (Utility Functions)`: Standalone helper functions (like error formatters, token generators, or date formatters) that can be reused anywhere in your project.

> api (application programming interface)
`API` stands for `Application Programming Interface`. It is a messenger or bridge (a set of rules or protocols) that allows two different software applications to talk to each other and share data.

- Simple Analogy: Think of an API like a waiter in a restaurant. You (the client/app) look at the menu and give your order to the waiter (the API). The waiter takes your request to the kitchen (the server/database), brings back your food (the data), and hands it to you.

Real-World Example:
Imagine a Weather App on your phone:
1. Your app doesn't store global weather data.
2. It sends an API request to an external weather server asking: "What's the temperature in Pune?"
3. The server sends back the temperature data via the API, which your app then displays on screen.

Key Points to Remember:
1. Communication Bridge: An API defines the rules on how other programs can request data from your server (e.g., defining routes like `/get-weather` or `/get-users`).
2. Third-Party Integration: APIs allow you to easily plug external services into your app—like adding Google Maps for location tracking, Stripe for payments, or a weather service for forecasts without building them from scratch.

> What is a `Port` and `Port Number`?
Think of your computer's `IP address` as an apartment building's street address, and a `port` as a specific apartment or door number inside that building.
When data (requests) arrives from the internet, the `IP address` gets the message to your computer, but the `port number` ensures the message goes to the exact right program or application running inside your computer (like your express web server).

In short, `Port` is the "doorway" itself; `Port Number` is the "door number" that identifies it.

- `Port`: A virtual communication endpoint (a specific delivery destination) in an operating system where network connections start and end, allowing different applications to send and receive data simultaneously.

- `Port Number`: A unique numerical label/identifier (ranging from 0 to 65535) assigned to a port that helps network protocols route incoming traffic to the correct application.

Key Concepts for Interviews:
1. `app.get(path, handler)`: Registers a route for HTTP GET requests sent to a specific path.
2. `req (Request Object)`: Contains all incoming data sent by the client (such as query params, body data, or headers).
3. `res (Response Object)`: Used to construct and send the response back to the client (using methods like `res.send()`, `res.json()`, or `res.render()`).
4. `(req, res) => {}`: A route handler (callback function) that runs automatically whenever a client accesses that endpoint.

> Essential NPM commands:
- `npm init`
1. Simple Analogy: Think of `npm init` like filling out the official business registration paperwork before opening a shop. It creates a `package.json file` that acts as your project's ID card and tracks everything it needs.
2. Simple Definition: A command-line instruction (or utility) (`npm init`) that initializes a new Node.js project by generating a `package.json file` to manage dependencies, scripts, and project metadata.

Then use `npm install <pkg>` afterwards to install a package and save it as a dependency in the package.json file.

- `npm init -y`
Definition: Initializes a new Node.js project by creating a default `package.json` file automatically (`-y` flag stands for "yes", which skips manual prompts).
In short, it initiates Node.js application.
Importance: It is the mandatory first step when starting any new backend project to create your project's "ID card" and track dependencies.

- `npm i package_name`
Definition: Downloads a specific package from the online npm registry, stores its code in the `node_modules folder`, and registers it inside your `package.json`.
In short, installs that particular package from the `npmjs` registry/website on your `node_modules folder`.
Importance: It is how you officially run your backend application, start your web server, or test your JavaScript scripts outside the browser.

- `node file_name.js`
Definition: Executes a JavaScript file using the Node.js runtime engine outside the browser.
Importance: Runs your backend code, server logic, or scripts via the terminal.

- `npm run start`
1. Simple Analogy: Think of `npm run start` like the manager officially flipping the restaurant sign from "Closed" to "Open" and turning on all the main kitchen power switches to begin service.
2. Simple Definition: A command-line instruction that tells Node.js to execute the specific startup script (usually pointing to your `index.js` or `server.js file`) configured inside the `package.json file`, booting up your server.

- `npm install express`
1. Simple Analogy: Think of `npm install express` like ordering a professional, pre-built kitchen equipment package from a supplier and having it delivered straight to your restaurant's storage room and registered on your master inventory checklist.
2. Simple Definition: A command-line instruction that downloads the `Express framework` from the *online npm registry*, saves its code locally in your project, and records it as a dependency in your *package.json file* so your application can use it.

> `Express Framework` vs. `Express App`
1. Simple Analogy: Think of the `Express framework` like a pre-packaged franchise restaurant blueprint and kitchen toolkit provided by a corporate company. Instead of building ovens, plumbing, and safety protocols from scratch, you buy a professional kit that already contains all the standard tools and structures you need.
2. Simple Definition: A third-party software library built on top of Node.js that provides pre-written code, helper functions, and structural rules to make building web servers and APIs fast and efficient.

1. Simple Analogy: Think of the `Express app` like one specific operating branch of that restaurant that you build using that kit. You set up its unique menu, assign its tables, and run its day-to-day operations.
2. Simple Definition: The individual instance or central engine created in your code by calling `express()` (e.g., `const app = express()`), which stores your project's unique routes, middleware, and configuration rules.

Are they the same or different?
They are different, but closely related:
The `framework` is the overall toolset and library you download from *npm*.
The `app` is the actual working machine you create out of that framework for your specific project. You import the framework, and then use it to build your app.

> `npm install dotenv --save` vs. `npm install dotenv`
1. Code-wise: They are identical. Both commands do the exact same thing in modern versions of npm—they download dotenv and add it to your package.json.
2. Flag-wise: The first command uses the `--save flag`. Historically (in older versions of *npm*), you had to type `--save` to force *npm* to write the package into your *package.json*. Today, *npm* does this automatically, making `--save` redundant.
3. Simple Definition: The standard modern command that downloads the `dotenv` package, installs it into your `node_modules` folder, and automatically records it inside your `package.json file` as a dependency.

> `commonjs` vs. `es module/module`
- Simple Analogy: Think of `CommonJS` like an old-fashioned paper mail order system. You call or send a request, wait right there for the package to be handed to you synchronously one by one, and then proceed.
- Simple Definition: The traditional Node.js module system that uses require() to import files and module.exports to export code. It loads modules synchronously (one at a time, blocking execution until loaded).

- Simple Analogy: Think of `ES Modules` like a modern online delivery network. Packages can be requested, bundled, and loaded efficiently in the background before execution even begins.
- Simple Definition: The official JavaScript standard module system (supported natively by browsers and modern Node.js) that uses import and export syntax. It supports asynchronous loading and static analysis.

Which one is better and why?
`ES Modules (ESM)` are generally considered better for modern development.
Here is why:
1. The Official Standard: It is the official JavaScript standard supported natively by all modern web browsers and Node.js.
2. Cleaner Syntax: `import` and `export` are cleaner and more readable than `require()` and `module.exports`.
3. Better Performance (Tree Shaking): `ESM` allows bundlers to analyze your code statically and strip out unused functions to make your final application lighter and faster.
Note: `CommonJS` is still important to know because many older Node.js libraries and legacy codebases still use it.

> What is a `CORS Policy`? `(Cross-Origin Resource Sharing)`
- Simple Analogy: Think of a VIP restaurant security door policy or a strict bouncer. Even though your restaurant is open, the bouncer will block people trying to walk in from an unauthorized street or competing venue unless they show an official guest pass confirming they are allowed inside.
- Simple Definition: A security feature implemented by web browsers that stops a frontend application running on one domain (like `localhost:5173`) from requesting data from a backend server on a different domain (like `localhost:3000`) unless the backend explicitly says it is allowed using *CORS headers*.

> What is a `Proxy`?
- Simple Analogy: Think of a restaurant host or a middleman. Instead of customers walking straight into the private kitchen or talking directly to the head chef, they hand their order to the host. The host takes it to the kitchen, brings back the food, and shields the inner kitchen details from the public.
- Simple Definition: An intermediary server (middleman) or software that sits between a client and a destination server, forwarding requests and responses while hiding network details, managing traffic routing, or bypassing local restrictions during development.

> What is `Mongoose`?
- Simple Analogy: Think of `Mongoose` like a strict construction inspector and translator standing between your app and the raw database. MongoDB is flexible and lets you store data however you want, but Mongoose enforces strict rules (schemas), checks your data types, validates required fields, and makes sure your data is clean before it ever gets saved to the database.
- Simple Definition: An `Object Data Modeling (ODM) library` for Node.js and MongoDB that provides a schema-based solution to model your application data, handling relationships, type casting, and validation automatically.

> Notes: 
1. `Blueprint` - A master template or plan that defines the structure, data, and behavior of an object before it is actually built.
e.g.: Think of a `blueprint` like an architectural floor plan for a house. It is the master plan that dictates the layout, dimensions, and rules of what you are going to build before a single brick is laid.

2. `Schema` - In databases and software (like Mongoose), a `schema` is a structural blueprint that defines the shape of documents within a collection-setting data types, validation rules, default values, and required fields.
e.g.: Think of a `schema` like a strict official government registration form or a job application checklist. It explicitly defines what fields must be filled out (e.g., *Name must be text*, *Age must be a number*, *Email is required*) and rejects any application that breaks those rules.

3. `Wrapper` - In software development, a `wrapper` is a piece of code, class, or function that "wraps around" an underlying, complex set of raw rules or data, giving you a simpler, cleaner, and more powerful set of tools to work with.
e.g.: Think of a `wrapper` like a TV remote control casing. Inside the remote are complex electronic circuits and raw electrical signals. The plastic casing (the wrapper) encloses all that complexity and gives you simple, easy-to-press buttons (like "Power" or "Volume Up") so you don't have to deal with raw wires.

> What is the `Mongoose Package`?
- Simple Definition: Mongoose is a Node.js package that helps your backend app talk to MongoDB easily by letting you set strict rules and helper methods for your data.

Key Points to Remember:
1. Rules (Schemas): Unlike raw MongoDB (which is completely flexible), Mongoose lets you enforce strict rules (e.g., "every note must have a title and it must be a string").
2. Built-in Validation: Automatically rejects invalid data before it wastes database space.
3. Easy Commands: Gives you simple JavaScript functions (`.find()`, `.save()`) instead of complicated database queries.

> What is `Data Modeling`?
- Simple Analogy: Think of data modeling like creating the architectural blueprints and interior design floor plan for a new building. Before you start throwing furniture and boxes into rooms, you carefully map out what rooms exist (collections), what goes inside them (fields and data types), and how hallways connect the rooms to each other (relationships).
- Simple Definition: The process of designing a conceptual blueprint (master template) of how data is structured, organized, stored, and related to other data within a database before writing code.

Why does it matter in Mongoose?
In MongoDB, data modeling is how you define your Mongoose Schemas. It ensures that every piece of user data, blog post, or product follows a predictable structure, enforces types (like making sure an age is always a *Number*), and properly links related data (like connecting a comment to a specific user).

> What are `Models` and a `Models Folder`?
- Simple Definition (`Models`): In Mongoose, a `Models` are *wrappers* around your Schema that gives you an interface to interact with your MongoDB database (allowing you to create, read, update, and delete documents for a specific collection like Users or Videos).
e.g.: Think of a dedicated store manager's desk for a specific category (like the "User Accounts Desk").
The blueprint/schema is the official store policy rulebook, but this desk is the actual operational station equipped with all the tools you need to create a new customer file, look up an existing customer, update their address, or delete their profile.

- Simple Definition (`Models Folder`): A dedicated directory in your project structure (usually inside `src/`) where you store all your database model files (e.g., `user.model.js`, `video.model.js`) to keep your code organized.

> Why `{timestamps: true}` is Important?
*Ans*: It tells Mongoose to automatically maintain two fields for every document: `createdAt` (when the record was first saved) and `updatedAt` (when it was last modified).
